关于Voxy模组区块管理方案

**区块保留（Retention）：**
- 玩家周围一定范围（比如 4-8 区块）的完整区块会完全保留，正常渲染
- 超出这个范围的区块不会被卸载，而是被 **转换成低精度的 LoD 网格**保存下来，继续显示但细节减少
- 走远之后原始区块数据会被释放，只保留 LoD 数据

**剔除（Culling）：**
- **视锥体裁剪**：
摄像机背后的区块直接不渲染
- **距离分级剔除**：距离越远，LoD 等级越低，到最远阈值直接不显示（类似雾效但更可控）
- **遮挡剔除**：被地形/建筑完全挡住的区块也跳过渲染

所以它不是简单粗暴的"远距离直接不渲染"，而是一个 **渐进式降级 + 分层次剔除** 的机制，
这也是它能上几千区块视距还不掉帧的原因。

如果远处的原始区块数据被释放，那保留的LOD数据具体包含了哪些信息？

Voxy 的 LOD 数据本质上是把原版区块 **体素化（voxelize）** 后的简化信息，大致包含这些：

**① 简化的方块类型**
不是完整的 Minecraft BlockState，而是粗粒度的分类——草方块、石头、水、空气、树叶等等。
每个体素只需要少量字节就能表示"这是什么"，不需要记录完整的属性（比如朝向、水位高度这类细节全丢了）。

**② 颜色信息**
每个体素带有对应方块的**平均颜色值**（从材质贴图采样）。这是 LoD 渲染的核心——远处看到的地形色彩就是靠这个撑起来的。

**③ 透明/不透明标记**
用来决定哪些体素需要剔除内部面，哪些要参与透明渲染（比如水面、玻璃要单独处理）。

**④ 多级 LoD 网格**
数据是**层次化**的。一个 16³ 的 section 会不断合并降采样成 8³ → 4³ → 2³ → 1³ 的金字塔结构，每一级代表不同的精度等级。离玩家越远，用越粗的层级。

**不保留的东西：**
- 方块的具体属性（朝向、含水、含雪等）
- 方块实体数据（箱子里的东西、告示牌文字等）
- 光照信息（重新计算或用简化光照）
- 红石状态、生物信息等

所以本质上就是把一个区块从"完整 Minecraft 数据"压缩成了一份**带颜色的简化体素快照**，

问：
如果原始区块数据量是100%的话，只保留LOD数据后大概还剩多少？
答：
粗略估算的话：

**原版区块数据（~150-200KB/chunk）：**
- 方块状态 ID（palette + bit-packed）：~120-140KB
- 高度图、生物群系、光照、区块实体等杂项：~30-60KB

**Voxy LOD 数据（~5-15KB/chunk）：**
- 每个体素：类型(1B) + RGB颜色(3B) + 标记(1B) ≈ **5 字节**
- 多级金字塔累加：~5-15KB（取决于保留几级）

所以大概只剩 **原数据的 5%~10%** 左右 📉

压缩比这么高的原因：
1. **丢掉了大量元数据**（区块实体、光照、NBT 开销等）
2.**方块属性被扁平化**——几百种 BlockState 压缩成几十种体素类型
3. **颜色只需 3 字节**，比存储完整方块状态省太多
所以这也是为什么能存几千个区块的 LoD 数据还不爆内存——本质上就是一份**高度压缩的体素快照**，不是原版数据的副本
