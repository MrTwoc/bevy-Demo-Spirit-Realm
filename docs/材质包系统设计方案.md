## 2. 数据结构和类型

### 2.1 `pack_metadata.rs` — pack.json Schema

```rust
use serde::Deserialize;

/// 材质包元数据（从 {pack}/pack.json 加载）
#[derive(Debug, Clone, Deserialize)]
pub struct PackMetadata {
    pub name: String,
    #[serde(default)]                    // 可选，默认 "1.0.0"
    pub version: String,
    #[serde(default)]                    // 可选，默认 ""
    pub description: String,
    #[serde(default)]                    // 可选，默认 None — 自动检测
    pub resolution: Option<u32>,
    #[serde(default = "default_format_version")]
    pub format: u32,                     // pack.json 格式版本，便于未来扩展
}

fn default_format_version() -> u32 { 1 }

impl Default for PackMetadata {
    fn default() -> Self {
        Self {
            name: String::new(),
            version: "1.0.0".to_string(),
            description: String::new(),
            resolution: None,
            format: 1,
        }
    }
}
```

### 2.2 `mod.rs` — 核心 Resource + Events

#### 分辨率级别

```rust
/// 材质分辨率级别
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct ResolutionLevel(pub u32);

/// 可用的分辨率列表（从目录结构扫描得到）
#[derive(Debug, Clone)]
pub struct AvailableResolutions {
    pub current: ResolutionLevel,       // 当前选中的分辨率
    pub available: Vec<ResolutionLevel>, // 所有可用的分辨率
}
```

#### Bevy ECS 事件系统

```rust
/// 资源包热切换请求事件（用户输入触发）
#[derive(Event)]
pub struct PackSwitchRequest {
    pub pack_name: String,
    pub resolution: Option<ResolutionLevel>,
}

/// 资源包切换完成事件（GPU 资源已上传）
#[derive(Event)]
pub struct PackSwitchCompleted {
    pub pack_name: String,
    pub resolution: ResolutionLevel,
    pub tex_size: u32,
    pub layer_count: u32,
}

/// 资源包切换失败事件
#[derive(Event)]
pub struct PackSwitchFailed {
    pub pack_name: String,
    pub error: String,
}
```

#### 资源包状态机

```rust
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum PackLoadState {
    Unloaded,
    LoadingTextures,
    BuildingAtlas,
    Ready,
    Error(String),
}

pub type PackResult<T> = Result<T, PackError>;

#[derive(Debug, Clone)]
pub struct PackError {
    pub kind: PackErrorKind,
    pub message: String,
}

#[derive(Debug, Clone)]
pub enum PackErrorKind {
    IoError,
    ValidationError,
    MissingTextures(Vec<String>),
    InvalidPackJson,
    NoResolutionAvailable,
}
```

#### 核心 Resource

```rust
/// 资源包运行时状态（替代旧 ResourcePackManager）
#[derive(Resource)]
pub struct ResourcePackState {
    // ── 元数据 ──
    pub packs_dir: PathBuf,
    pub selected_pack: Option<String>,
    pub current_pack: PathBuf,
    pub available_packs: Vec<String>,
    pub metadata: PackMetadata,
    pub resolution: AvailableResolutions,

    // ── 状态 ──
    pub load_state: PackLoadState,

    // ── 纹理数据 ──
    pub texture_cache: HashMap<String, TextureData>,
    pub atlas: Option<TextureAtlas>,
    pub block_texture_map: HashMap<(u8, String), String>,
    block_uv_array: [[Option<UvCoord>; 3]; 256],

    // ── 方块定义 ──
    pub block_definitions: HashMap<u8, BlockDefinition>,
}

/// 纹理原始数据（替代旧 (Vec<u8>, u32, u32) 元组）
#[derive(Debug, Clone)]
pub struct TextureData {
    pub pixels: Vec<u8>,
    pub width: u32,
    pub height: u32,
}
```

#### 保留不变的公共类型

以下类型保持原有数据布局，仅位置从 `resource_pack.rs` 迁移到 `mod.rs`：

- `VoxelMaterial` — AsBindGroup 自定义材质
- `TextureAtlas` — Texture Array 像素数据
- `TextureInfo` — UV + layer 信息
- `RESOURCE_PACKS_DIR` — 常量 `"assets/resourcepacks"`

## 3. 系统流程设计

### 3.1 启动加载流程（Startup chain）

```
1. load_block_definitions_system
   → 读取 assets/blockstates/*.json → BlockDefinitionRegistry
   → 初始化全局 BlockPropertiesTable (OnceLock)

2. load_resource_pack_system
   → 扫描 {packs_dir} → available_packs
   → 解析 pack.json（可选）
   → 确定纹理目录（textures/ 或 textures_{N}x/）
   → 加载所有 PNG → texture_cache
   → 验证纹理完整性
   → build_atlas() → TextureAtlas
   → 设置 load_state = Ready

3. setup_world_system（需修改参数类型）
   → 从 ResourcePackState 读取 atlas → 创建 GPU Image
   → 创建 VoxelMaterial 句柄（Opaque + Blend）
   → 创建 UvLookupTable → AsyncMeshManager
```

### 3.2 多分辨率纹理目录解析

```
pack_loader.rs: resolve_texture_dir() 逻辑：

pack.json 无 resolution 字段:
    → 自动检测模式
    → scan_for_resolutions(pack_path)
        1. 识别 textures_{N}x 格式子目录
        2. 检查 textures/ 目录
        3. 返回 AvailableResolutions { current: 最大分辨率, available: [...] }

pack.json 有 resolution: N:
    → 显式分辨率模式
    → 优先 textures_{N}x/
    → 回退到 textures/（单分辨率模式）
    → 否则报错 NoResolutionAvailable
```

### 3.3 统一材质包目录结构

```
assets/resourcepacks/
└── {pack_name}/
    ├── pack.json                ← 元数据（可选）
    ├── textures/                ← 默认纹理（单分辨率模式）
    │   ├── dirt.png
    │   ├── grass_block_top.png
    │   └── ...
    └── textures_{N}x/           ← 可选多分辨率目录
        ├── textures_16x/
        │   ├── dirt.png
        │   └── ...
        └── textures_32x/
            ├── dirt.png
            └── ...
```

## 4. 热重载 / 运行时切换机制

### 4.1 事件驱动架构

```
┌─────────────┐  PackSwitchRequest  ┌───────────────────────┐
│ 用户输入     │ ─────────────────→  │ 1. switch_pack_system   │
│ (UI/控制台)  │                   │    - 加载新纹理          │
└─────────────┘                    │    - build_atlas()       │
                                   │    - 更新 ResourcePackState│
                                   │    - 创建新 GPU Image     │
                                   │    - 创建新 VoxelMaterial │
                                   └───────────┬─────────────┘
                                               │
                                    PackSwitchCompleted
                                               │
                                               ▼
                                   ┌───────────────────────┐
                                   │ 2. update_chunk_       │
                                   │    materials_system    │
                                   │    - 遍历所有 chunk 实体 │
                                   │    - 更新 MeshMaterial3d│
                                   │    - 更新 UvLookupTable │
                                   └───────────────────────┘
```

### 4.2 `switch_pack_system()` 流程

1. 在新 pack 路径上执行完整加载
2. 创建新 GPU Image（Texture Array 2D）
3. 释放旧 Image 资源
4. 创建新的 VoxelMaterial（Opaque + Blend）
5. 释放旧材质资源
6. 更新 Shared Resources 句柄
7. 更新 AsyncMeshManager 的 UV 表（Arc 原子替换）
8. 发送 PackSwitchCompleted / PackSwitchFailed 事件

### 4.3 `update_chunk_materials_system()` 实体更新

- 遍历所有带 ChunkCoordComponent 的实体
- 将 MeshMaterial3d 更新为新材质
- 标记 DirtyChunk（触发网格重建使用新 UV）
- 更新 LoadedChunks 中所有 entry 的 solid_material_handle

### 4.4 UvLookupTable 热更新（Arc 原子替换）

```rust
impl AsyncMeshManager {
    pub fn update_uv_table(&mut self, new_table: UvLookupTable) {
        self.uv_table = Arc::new(new_table);
    }
}
```

工作线程通过 `Arc::clone` 获取引用，主线程替换 Arc 后：
- 新任务获取新表
- 已完成但未提交的任务使用旧表（可接受，后续脏块重建时自动更新）

## 5. 验证与错误处理

### 5.1 验证项（pack_validator.rs）

| 检查项 | 级别 | 说明 |
|-------|------|------|
| block textures 存在性 | Error | 遍历 block definitions 的 textures.{top,bottom,side}，检查是否在 texture_cache 中存在 |
| 未使用纹理 | Warning | texture_cache 中未被任何 block definition 引用的 PNG |
| 分辨率一致性 | Warning | 所有纹理尺寸是否一致 |
| pack.json 格式 | Error | serde 解析失败时报告具体字段和位置 |

### 5.2 错误处理策略

| 场景 | 策略 |
|------|------|
| pack.json 格式错误 | `error!()` 日志 + PackLoadState::Error |
| 缺少纹理 | `error!()` + 使用粉红/黑紫占位纹理继续加载 |
| 分辨率不一致 | `warn!()` + 继续运行 |
| 缺失 pack.json | 自动检测模式，不报错 |
| 缺失 textures_32x/ | 回退到 textures/ 或下一个可用分辨率 |
| 热切换失败 | 发送 PackSwitchFailed 事件，保持当前材质不变 |
